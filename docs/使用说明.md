# 跑伴 RunMate v1.8.11 使用说明

> 配合「i大工-体质测评-健康长跑」使用的独立安卓 App
> 无需 root / 无需 Google 服务 / 不读取你 i大工 的任何数据，定位与提醒全部在本机完成

## 0. v1.8.11 更新速览（登录失败分流 · 全部弹窗手动确认）

> 本版针对两项实报问题：① 登录输完短信验证码显示「验证会话被学校服务重置」；
> ② App 内各种临时弹窗显示不全，要求全部改为手动确认才能关闭。

**① 登录「验证会话被学校服务重置」——再次实测推翻旧结论，按失败真实原因分流**

用真实账号把 **App 的 OkHttp 客户端逐行复刻**（同超时配置、同请求头、同字段序、
同 Cookie 策略）在沙箱里全链路探针，实测：**学校 CAS 的验证会话其实非常稳定**——
短信码输错重试、发送短信后再刷图形验证码、等 6 分钟再提交，会话全部存活；
协议本身（图形码 → 发短信 → 提交短信码）也一路畅通。手机上仍报「会话被重置」，
最大嫌疑是**网络瞬断/超时**——而旧版把一切失败（含网络错误）都显示成
「会话被学校服务重置」并强制重新登录，既误导排查方向、又白烧短信配额。本版分流：

| 失败原因 | 旧版行为 | v1.8.11 行为 |
|---------|---------|-------------|
| 网络超时/瞬断 | 报「会话被重置」+ 强制重登 | **不重登**：短信码保留在输入框，直接再点「完成登录」 |
| 会话真失效（回登录页） | 强制重登 + 重新发短信 | **自动重登 + 同一短信码重提一次**——成功则无感救回，仍失败才重发 |
| 服务端「请求出错」异常页 | 报「会话被重置」 | 如实提示，对话框保留（execution 不变）可直接重试 |

另外：每次失败自动把 HTTP 状态码/终态 URL/页面指纹写入崩溃日志
（设置 → 查看崩溃日志），反馈给开发者可精确定位，不再靠猜。

**② 二次认证对话框：短信码为空不再关闭**
旧版点「完成登录」按钮对话框必关——没填码就点一下，整个流程作废重来一遍。
现在为空时在对话框内直接提示，填完再点即可。

**③ 全部临时弹窗改为需手动确认（用户实报「显示不全」）**
- App 内所有一闪而过的 Toast 全部移除，统一改为对话框：**必须点「确定」才能关闭**，
  长文案完整可读——覆盖设置 / 接口 / 地图 / 标定 / 跑步 / H5 捕获 / 更新检查全部页面；
- 跑步页下拉刷新：成功时静默（右上角数字已就地更新），仅失败/异常弹完整原因；
- H5 捕获页未带会话进入：点「确定」确认后才退出页面（旧版提示一闪而过直接退出）；
- 后台跑步服务启动失败：改高优先级系统通知（下拉展开全文，点按进入 App）——
  后台无法弹对话框，这是 Android 上完整展示长文案的正确通道。

## 0.1. v1.8.10 更新速览（登录「会话已过期」实测根治 · 设置页闪退修复）

> 本版针对两项实报问题：登录输完验证码报「会话已过期」、设置页点「测试提醒」后偶发闪退。
> 第一项经真实账号全链路实测（图形验证码自动识别 → 真实发送短信 → 错码提交探针），
> 结论与修复如下。

**① 设置页闪退（IllegalStateException: not attached to a context）——修复**
点「测试提醒」后 App 会延迟 4.5 秒弹出三通道自检结果；若这 4.5 秒内离开设置页，
Fragment 已脱离宿主，回调仍去取资源/弹窗即闪退。现在回调先无条件释放播放器，
已脱离则安静放弃弹窗，不再崩溃。

**② 登录「会话已过期」——实测结论 + 四重加固**
用真实账号把整条链路跑通后发现：**你的账号密码和 App 的协议格式都没有问题**，
学校二次认证服务端状态机本身也很健壮（实测等短信 75 秒后提交、连续输错码重试、
发送后刷新图形码，流程全部存活）。「会话已过期」是学校服务波动重置会话所致。
本版从四个维度对齐浏览器行为、对波动免疫：
- 登录页加载→提交之间加 2.5 秒人节奏（模拟真实用户填表耗时）；
- 请求头补齐 Origin / Accept-Language / Accept / Upgrade-Insecure-Requests（逐字节对齐 Chrome 抓包）；
- 表单字段序改为学校网页实际提交序；
- 响应若是「无错误文案的登录页」（= 服务端把本次会话重置了，不是密码错），自动换新会话重试，最多 3 轮。

**③ 「会话已过期」提示语重写**
现在会明确告诉你是学校服务重置（不是密码或验证码错误）、已自动重新登录、
重发短信受一分钟限频，避免连续重试烧掉当日短信配额。

> 上一版（v1.8.9）速览：二次认证三连修 · H5 捕获页死循环根治（见下方 §0.2）。

## 0.2. v1.8.9 更新速览（二次认证三连修 · H5 捕获页死循环根治）

> 本版专修上一版短信二次认证（学校统一认证新启用）落地后暴露的三个问题，全部经真实账号实测定位。

**① 「一点发送就刷新图形验证码，每次登录都验证码过期或无效」——根治**
实测发现：短信发送成功后，服务端二次认证流程进入「待提交短信码」状态，此时再请求图形验证码会**重置整个流程**。旧版在发送成功后自动刷新图形码图片，恰好踩中这个坑——之后提交短信码必报「验证码过期或无效」。
现在发送成功后不再自动刷新图形码（对齐学校网页端行为）；需要重发时先点图片刷新、输入新图形码再点发送即可（界面有提示）。

**② 「第二次发送验证码显示 get_session_error」——修复**
与①同根因：流程被重置后发送通道整体作废。现在收到该错误会**自动重启登录流程**并重新弹出二次认证对话框，输入新图形码即可继续，不会卡死。

**③ 短信码输错后重试永远失败——修复**
实测短信码提交后服务端会推进会话状态（旧状态立即作废），旧版重试仍用旧状态所以永远失败。现在自动采用服务端返回的新状态，短信码输错直接再输一次就行。

**④ 「重新捕获 H5 参数」页面一直自动刷新——根治**
自动流程把统一认证的登录页误判成「已登录」，反复导航→弹回→再导航形成死循环，每轮还会作废正在输入的验证码。现在认证页绝不自动导航；检测到短信/图形验证界面时暂停全部自动化并提示操作步骤，手动完成验证后自动继续捕获；自动重试最多两轮即停，页面完全交还手动控制。
（「H5 参数」= 健康长跑接口的 userId/amId/pmId/sign + 访问令牌 + 隧道会话，换学期或令牌失效时需重新捕获一次。）

**⑤ 其他**：无已保存会话也能打开 H5 捕获页（自动填表 + 页面内完成验证）；彻底删除操场环线遗留数据文件。

## 0.3. v1.8.8 更新速览（登录失败根因修复 · 预录语音 · 移除操场环线）

本版解决三项实报问题，第一项是「突然登录不上」的根因修复：

- **登录失败已定位并修复（学校新启短信二次认证）**：经真实账号实测——账号密码
  验证是通过的，问题出在学校统一认证近期新增了「短信二次认证」环节：密码验对
  后还要图形验证码 + 手机短信验证码两步，旧版不认识这个页面，误报「用户名或
  密码错误」。本版起登录会自动弹出二次认证对话框：看图输入图形码 → 点「发送
  短信验证码」（短信发到绑定手机）→ 输入收到的短信码，完成后自动继续原生一键
  配置；短信码输错可直接重试，图形码错/发送太频繁等服务器反馈均有明确提示；
- **语音提醒改用预录音频（彻底弃用 TTS 引擎）**：此前语音依赖系统 TTS 引擎，
  各品牌 ROM 引擎缺失/无中文语音数据时反复不可用。本版改为 9 条预录语音随
  App 打包（「跑步已开始」「前方打卡点，请准备」「打卡成功」「注意，未确认
  打卡，请减速返回或留意手机」等），任何设备上表现完全一致；跟随媒体音量
  播放；「测试提醒」即点即播，自检显示真实播放结果；
- **移除地图页「操场环线」**：该功能仅为参考显示、不参与打卡检测计算，按
  反馈删除（开关与蓝色轨迹线一并移除；检测只看你自建的打卡点列表）。

> 上一版（v1.8.7）速览：TTS 引擎多链兜底 · 震动通知属性归类 · 锁屏卡片实底（见下方 §0.4）。

## 0.4. v1.8.7 更新速览（TTS 引擎多链兜底 · 震动通知属性 · 锁屏卡片实底）

本版针对用户实报的三个问题（提示音经 v1.8.6 重修已正常，本版未改动）：

- **语音引擎不可用（多链兜底重做）**：旧版只尝试系统默认 TTS 引擎一次，默认
  引擎缺失/损坏/无中文语音数据的设备（MIUI、ColorOS 等 ROM 常见）语音通道
  直接判死。本版改为「引擎链」逐个尝试：系统默认 → Google → 小爱 → 讯飞 →
  百度 → 三星 → 扫描出的其余引擎（以系统注册的 TTS 服务为准，不写死名单），
  初始化失败或缺中文语音数据自动换下一个，全链试完才如实报「不可用」；
- **震动「显示触发、手上无感」（补通知属性）**：旧调用不带任何属性，系统
  归为「未知用途」震动，部分 ROM 在静音/勿扰/触感策略下将其静默吞掉。
  本版按 Android 8.0/11 分级挂「通知震动」属性，归入系统通知震动通道；
  三档提醒波形再加长；
- **锁屏卡片背景透明（实底色）**：通知启用 colorized 实心品牌蓝；媒体会话
  补 512 渐变实底「专辑图」——Android 11+ 锁屏系统媒体卡的背景取自专辑图，
  无图时部分 ROM 直接透出壁纸。本版起锁屏卡片为实色不透明，附缩略图，
  观感对齐音乐软件；
- **「测试提醒」自检改为真实结果**：旧版自检里「✓ 震动已触发」是写死的静态
  文案——这正是「显示触发但没震」被掩盖的原因。本版按实际调用结果如实
  展示：语音行显示当前引擎名（如「引擎：小爱语音引擎」），震动行给出
  真实状态与失败原因（无震动模块/调用异常/开关未开），失败附排查指引；
  TTS 不可用时弹窗提供「去系统语音设置」直达入口（安装 Google / 小爱 /
  讯飞任一引擎并下载中文语音数据后回来重测即可）。

> 上一版（v1.8.6）速览：提醒三通道重修 · 锁屏媒体卡片 · 下拉刷新 · 1m 精度（见下方 §0.5）。

## 0.5. v1.8.6 更新速览（提醒三通道重修 · 锁屏媒体卡片 · 下拉刷新 · 1m 精度）

本版针对用户实报的四个问题：

- **语音播报 / 提示音 / 震动全部无效（彻底重修）**：三个根因逐一根治——
  1) 语音走错了音量通道：旧版 TTS 挂在系统「导航」音量通道上，绝大多数设备
     该通道默认极小甚至为 0，等于永远静音；本版改走「媒体」通道（跑步听歌
     用的音量），并如实检测中文语音包（缺失时自动降级为提示音+震动，旧版
     会谎报就绪导致无声）；
  2) 提示音固定走媒体流，媒体音量为 0 的设备上完全无声；本版自动切「通知」
     通道兜底（通知通道几乎总开着、不受媒体音量影响）；
  3) 震动波形加长（旧版 35/60ms 在口袋/臂包里基本无感），并修复 Android 7.x
     上震动整段丢失的兼容缺陷；
  设置页新增**「测试提醒」**按钮：当场播报语音+提示音+震动，数秒后给出三通道
  自检结果（含 TTS 引擎诊断）——手机上即可验证哪一通道有问题；
- **锁屏显示改为音乐软件样式（按用户澄清重做）**：锁屏上不再显示整个应用页面，
  而是一张媒体卡片，框里只显示关键信息——标题=官方打卡距离（如「官方打卡
  826 m」），副标题=漏卡警示 / 检测区待确认 / 已确认进度 + GPS 里程，附
  「立即核对 / 结束」按钮；Android 11+ 在锁屏与快捷设置顶部媒体区渲染。
  v1.8.4 的「整页显示在锁屏上」方案随之移除；
- **跑步页下拉刷新**：在「跑步」页向下划屏幕即触发服务端距离查询/核对——
  成功静默更新右上角数字并给出简报，失败提示原因；完整响应详情仍走点按
  「服务端距离」入口的弹窗；
- **检测参数最小可调精度 1m**：默认检测半径（原 5m 步长）、预告距离（原 10m
  步长）、单点编辑半径（原 5m 步长）全部改为 1m 步进；确认阈值原本即 1m。

## 0.6. v1.8.5 更新速览（更新检测提速：GitHub 优先 + 每次启动必查）

本版针对应用内更新机制做两项改进：

- **检查顺序反转：先查 GitHub，再查本站服务器**：新版本总是先发布到 GitHub
  Release，网站随后才同步（可能滞后数小时）。旧顺序先查网站，窗口期内会误判
  「已是最新」。本版起 GitHub 上的新版第一时间就能收到升级提醒；
- **每次进入 App 都自动检查**：旧版每天最多检查一次，可能错过当天发布的新版。
  本版起冷启动、后台切回前台都会静默检查；同次使用内 5 分钟去重，仍是最新则
  完全不打扰。手动「设置 → 检查更新」不受影响；
- **双通道合并与下载策略**：任一通道发现新版即提醒；两边都有更新时取版本更高
  者，同版本优先从本站服务器下载（国内更稳、带完整性校验）；GitHub 不可达时
  自动落服务器通道，反之亦然；
- **修复隐患（GitHub 链接小写化）**：本版发布当日实测 GitHub 侧该仓库精确大小写
  名称的路由（API/网页/下载）一度整体 404，小写形式始终正常。App 内所有 GitHub
  链接与下载地址已统一改用小写仓库名，规避检查/下载偶发失败。

> 操场环线说明（见下方 §0.3）。

## 0.7. v1.8.4 更新速览（标定页列表 · 锁屏显示应用）

本版修复两项实报问题：

- **标定页「添加打卡点」只能看到一个点位（修复）**：旧版点位列表用的滚动控件
  嵌在整页滚动容器里，在部分机型上只测出第一个条目的高度——不管保存了多少个
  点都只显示一个。本版改为逐条渲染，所有点位必然完整展示（点击可编辑、× 可删除）；

  仍被锁屏挡住。本版起：跑步进行中锁屏后，按电源键/亮屏直接显示跑步界面，无需
  解锁；停止跑步立即恢复正常锁屏。注意：需保持跑伴在跑步前处于前台（先按 Home
  回桌面再锁屏则仍显示桌面/锁屏，从通知点回跑伴即可）；
- **地图页「操场环线」说明**：它是大工操场跑道的参考轨迹线（蓝色线条），仅用于
  对照选点与跑位参考，不参与打卡检测计算（检测只看你自己建的打卡点）。
  （v1.8.8 注：该开关已按反馈移除。）

## 0.8. v1.8.3 更新速览（原生一键配置 · 五项问题修复）

本版解决五项实报问题，其中第一项是「校外/已登录却拿不到令牌」的根治性重构：

- **原生一键配置（根治「已登录却无法获取 token / 账号未捕获 / webvpn 会话未建立或已过期」）**：
  「接口」页输入学号密码登录成功后，不再打开 H5 捕获页去等嗅探——App 原生完成整套
  认证链（CAS 统一认证 → WebVPN 统一身份 → 隧道前缀本地计算 → 体育平台免密跳转 →

## 2. 录入 8 个打卡点（两种方式，二选一或混用）

### 方式 A：现场标定（推荐，最准；v1.9.1 起在「地图」页内完成）
1. 人站到打卡点 **中心位置**（操场点位就站在第 4 跑道那条弧线上）；
2. 「地图」页右下角十字按钮 → 打开底部标定面板（身后的地图仍可见，蓝点/精度圈跟随），等精度收敛（±10m 内更佳，面板实时显示精度/卫星数）；
3. 选采集时长（10/20/30 秒）→ **开始平均标定**：App 会做精度加权平均并给出「±精度 · 离散半径」；
4. 命名（如「西山操场1号」）→ **保存为打卡点**。半径建议默认（App 会按 GPS 精度自动给 20~30m）。保存后地图即时长出新图钉，面板不关可继续标定下一个点。

### 方式 B：地图选点（v1.2.0 准星确认流）
1. 「地图」页（图源为高德，国内直连秒开）：双指缩放到最深 20 级（约 0.1m/像素，跑道线清晰可见）；卫星/街道可切换（卫星约 18 级、街道 20 级，卫星更深处自动放大 18 级瓦片）；
2. **点按或长按**地图任意位置 → 出现**橙色准星标记**与底部确认栏（实时显示该点 WGS-84 坐标）；
3. **拖动准星**微调位置，双指放大地图核对落点（准星几何中心即精确坐标点），确认无误后点 **「确认添加」**；
4. 弹出新增面板：可查双制式坐标、手改坐标、调半径、命名 → 保存；点「取消」则移除准星不建点；
5. **拖动图钉**可微调已有点；点图钉可编辑/删除；
6. 已知 GCJ-02 坐标（如从高德取的）→ 面板里切 GCJ-02 制式输入，自动换算。

> 地图上的蓝色圆点是你的实时位置（带半透明精度圈）：**蓝点 = GPS 定位**，**灰点 = 网络定位（精度较低仅作参考）**。若蓝点长期不出现，到开阔处等 GPS 首次定位。

> 也可以先用 B 粗放 8 个点，再逐个到现场用 A 精修（「地图」页点图钉即可编辑；跑步页列表也可点开编辑）。

## 3. 跑步（配 i大工 原 App 双开使用）

> **v1.3.0 起随时可定位查看**：不开跑步，「跑步」页即实时定位预览（标题显示「定位预览 · GPS ±Xm」/「网络定位 ±Xm」），最近点位距离与雷达方向同步刷新；「地图」页左上角常驻定位源徽章（GPS 蓝/网络橙/搜索中灰），点按徽章可看定位源说明。想开跑随时点「开始跑步」。
>
> **v1.9.2 起状态卡大数字 = 「已跑里程（km）」**（跑步中最重要的数字，跑步中/刚结束实时刷新）；最近点位名称与距离移至大数字下方一行。跑步页筛选条只留「全部/各分组」（「自动」分组已删，想看哪组自己点）。

1. 正常打开 i大工 的健康长跑跑步页（开始计跑）；
2. 回到跑伴 → 「跑步」页 → **开始跑步**（出现常驻通知=后台运行中）；
3. 戴上耳机，正常跑。跑伴会自动：
   - 接近点位（默认 60m，可调）：语音「前方 XX 米，点位名，请准备」；
   - 进入检测圈：提示音 + 「已进入 X 号检测区」；
   - **API 判定开启时**：出圈后宽限期内核查「跑步距离」接口，距离增量达标 → 语音「X 号点，打卡成功」+ 轻震；未达标 → 语音「注意，X 号点未确认打卡」+ 急促震动 + 警示音 —— 这时**减速折返再过一次该点**即可（漏卡点位状态会自动重置等待补卡）；
   - 结束时弹小结（确认/漏卡清单 + 用时 + 自测距离）。
4. 息屏不影响运行（前台服务 + WakeLock + 电池白名单）；
5. **立即核对（v1.3.0）**：跑步中随时点按首页右上「服务端距离」，下个瞬间即请求一次 findExtExercise 并核对（不用等自动轮询）；未跑步时点按则直接查询一次官方距离。
6. **下拉刷新（v1.8.6）**：在「跑步」页任意位置向下划屏幕，即触发同样的查询/核对——成功静默更新右上角数字并给出简报，失败提示原因；点按入口仍保留完整响应详情弹窗。

## 4. 启用「API 判定」（漏卡提醒的开关）

不开启时只有进出圈提示，**无法判定是否真的打上卡**。开启步骤：

1. 按《i大工-健康长跑_API接口文档.md》§5 抓包一次（约 5 分钟，拿到 userId/amId/pmId/sign 与 Authorization 令牌）；
2. 「接口」页「**健康长跑距离 findExtExercise**」模板 **v1.3.0 起已预填实测接口**：把抓包的 `amId/pmId/sign/userId` 填进请求体、`userId:accessToken` 整串粘到令牌栏（校外把 URL 换成 WebVPN 隧道地址）→ **发送测试**直至能提取到距离值（旧版本如模板为空，App 升级后自动补填）；
3. 「设置」→ 打开「API 判定」。

**打卡核对判定标准**（= 服务端距离变长 且 此时经过打卡区域）：

```
跑步全程：每 15s 锚点轮询一次官方距离（维持基线新鲜）
进入检测圈（半径可设，默认 10m）→ 基线 = 进区前最后一次轮询到的官方距离（30s 内有效）
    区内每 N 秒(默认3s)轮询：距离增量 ≥ 内置阈值 50m（v1.9.2 起固定，RFID 命中一次=+100m/+200m 必触发）
        ⇒ 打卡成功 ✓（语音+短震）
    出圈后宽限(默认15s)仍无增量 ⇒ 漏卡！强提醒 ⚠（减速折返再过一次即可补卡）
```

> 基线为什么取「进区前」的距离：RFID 读卡器注册打卡往往先于 App 的下一次轮询——
> 若等进区后才取基线，基线可能已包含这次 +100m，就永远检测不到增量了（v1.3.0 修复）。

## 10. 常见问题

- **跑步中没声音**：检查媒体音量（语音跟随媒体通道）；自检报「TTS 不可用」时到系统设置 → 文字转语音（TTS）输出，安装 Google / 小爱 / 讯飞任一引擎并下载中文语音数据，就绪后自检会显示引擎名。
- **震动没震感**：自检显示「✓ 已下发」但手上无感 → 系统设置 → 声音与触感，调高「震动强度」并开启「触感反馈」；勿扰模式会拦截通知震动，跑步时建议关闭勿扰或改为「允许震动」。
- **锁屏卡片透明/看不清**：v1.8.7 起锁屏卡片为实色品牌蓝不透明；若仍透明请确认已升级到 v1.8.7，并检查系统「锁屏通知」样式设置。
- **被系统杀了**：确认电池白名单；小米/华为等在设置里再允许「自启动」。
- **坐标显示怎么和网上查的不一样**：网上多为高德 GCJ-02（大连地区偏移约 450m），App 显示的是 GPS 原始 WGS-84；两种制式在弹窗中同时展示，输入时可切换。
- **地图上的图钉位置准吗**：准。地图用高德瓦片（GCJ-02 制图），App 在显示和点选两侧自动换算，图钉压住的位置就是存储点位对应的真实地面位置（v1.2.0 修正算法后已实测验证）。
- **蓝点是灰色的/显示「网络定位」**：室内或遮挡下 GPS 无法锁定，App 自动回落到网络定位（误差几十至几百米，坐标已自动归一只作参考）；到室外开阔处静止半分钟，GPS 锁定后自动切换为蓝点（点地图顶部徽章可看说明）。
- **网络定位和 GPS 差多少**：GPS 室外精度一般 3~10m；网络定位（基站/WiFi）几十至几百米。跑步判定用的坐标始终 GPS 优先（20~30s 内有 GPS 就忽略网络定位），不受影响。
- **不开跑步能看定位吗**：能（v1.3.0）。「跑步」页自动进入定位预览，「地图」页看蓝点/徽章。
- **令牌过期**：接口页出现 401/提取失败 → 重新登录 i大工 → 重新抓一次 Cookie 更新令牌。

## 11. 隐私与边界

- 所有数据（点位、设置、令牌）仅存本机 `filesDir`；不上传任何服务器；
- 定位检测全部在本机完成；接口调试只访问你配置的那一个 URL；
- 仅供个人跑步提醒与本人账号接口调试，请勿用于改成绩/批量请求等用途。
